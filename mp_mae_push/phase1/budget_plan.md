## 동시 실행 규칙

1. 무거운 적합(XGBoost·LightGBM·CatBoost·임베딩)을 돌리는 트랙은 동시에 2개까지. 가용 RAM이 1.2 GiB뿐이라 프로세스당 최대 RSS 1.5 GB를 넘는 작업(외부 데이터 약 25만 행 적합, 언어모델 미세조정)은 단독으로 실행한다. **2단계 전에 다른 프로그램을 닫아 가용 RAM을 4 GiB 이상 확보해 주시면 실패 위험이 줄어든다.**
2. XGBoost는 n_jobs=8로 고정한다(스레드 수가 적합 결과를 바꾸므로). 동시 실행으로 느려질 수는 있어도 수치는 같다. 스레드 수와 seed는 어떤 경우에도 test 결과로 고르지 않는다.
3. 프로세스 병렬(multiprocessing, joblib loky)은 샌드박스에서 실패하므로 쓰지 않는다. 병렬은 모델 내부 스레드와 독립 서브프로세스로만 한다.
4. 오래 걸리는 작업은 스크립트 + 중간 저장(Optuna는 SQLite)으로 실행해 세션이 끊겨도 이어서 진행한다.

## 중단 기준

- 가설별: 가설 표의 '실패 판정 기준'. 실패한 가설은 ledger에 그대로 남기고 다음으로 넘어간다.
- 트랙별: 트랙 CPU 상한의 100 %에 도달하면 멈추고 보고한다. 상한을 넘겨야 하면 먼저 묻는다.
- 전체: validation MAE가 20 K 아래로 내려가는 결과가 나오면 즉시 9절 누설 감사를 하고, 통과 전에는 결과로 쓰지 않는다.
- T8: 각 단계가 실패 기준에 걸리면 다음 단계(더 비싼 모델)로 가지 않는다. 대량 LLM 호출은 500분자 파일럿의 실측 토큰으로 비용을 다시 제시한 뒤 진행한다.
