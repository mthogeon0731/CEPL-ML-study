## 트랙 X — 오차 XAI: "MAE가 왜 더 안 줄어드는가"

목표는 "어떤 특징이 중요한가"가 아니라 **남은 오차 약 25 K가 어디서 오는지 몫을 나누는 것**입니다. 대상 모델은 LGB(F0+F3+F5)와 GIN 하이브리드.

### X1. 오차 예산표 (가장 중요한 산출물)
random·scaffold 각각, validation MAE를 다음 몫으로 나눈 표와 그림 하나:
1. **라벨 잡음**: 1단계 추정(약 2 K) 재사용.
2. **2D 표현으로는 구분 불가능한 몫 (하한)**: 모델 입력이 같거나 거의 같은데 정답이 다른 쌍에서 계산. 어떤 모델도 한 쌍에서 평균 |Δy|/2보다 잘할 수 없음.
   - (a) InChIKey 첫 블록이 같은 쌍(입체 이성질체), (b) F0+F3+F5 특징 벡터가 사실상 같은 쌍, (c) Tanimoto ≥ 0.95 최근접 쌍(activity cliff). 각 집합의 크기, 평균 |Δy|, 전체 MAE에 주는 몫.
3. **데이터 밀도 부족**: 최근접 train 유사도·이웃 수 구간별 오차 → 이웃이 충분한 분자의 오차 수준을 "밀도가 충분했다면"의 기준으로 삼아 몫 추정. 1단계 학습 곡선 외삽과 대조.
4. **모델·특징 부족(나머지)**: 위 셋으로 설명 안 되는 몫.
각 몫에 범위(낙관–보수)를 달고, 몫끼리 겹치는 부분은 겹친다고 적기.

### X2. 오차 모델 + SHAP ("어떤 분자가 틀리나")
- train OOF의 |오차|(그리고 부호 있는 잔차 따로)를 target으로 LightGBM 메타모델 학습. 입력: F0·F3·F5 + 최근접 유사도·이웃 수 + 반복측정 수 + 분자 크기 + 1단계 계열 표지.
- validation에서 메타모델이 오차를 얼마나 설명하는지(Spearman, 상위 10 % 적중) 먼저 보고. 설명력이 낮으면 "오차는 특징으로 예측 불가 → 무작위에 가까움"이 결론.
- TreeSHAP 상위 15 + 묶음(대칭·유연성·수소결합·모양·극성·크기·유사도·라벨 품질) 단위 합. 대조군 셋 적용.

### X3. 고융점 과소예측의 원인 가르기
- 같은 특징으로 **분류기**(y > 550 K 여부, y < 250 K 여부) 학습 → validation AUC·PR.
  - AUC가 높은데 회귀가 과소예측 → 정보는 있는데 손실·평균 회귀 문제 → 분위수/구간 가중으로 풀 여지.
  - AUC가 낮음 → 특징에 정보가 없음(결정 패킹 등).
- >550 K 분자(OOF + validation)에 대해: SHAP 기여 합이 평균 분자 대비 얼마나 올려 주는지와 실제 필요한 양의 차이, 가장 닮은 train 분자 5개의 라벨 분포, 과소예측이 심한 30개를 구조와 함께 한 장 그림으로.

### X4. 최종 모델 설명 (기존 방식 차용)
- LGB(F0+F3+F5) TreeSHAP: 전역 상위 15, 묶음별 기여, 대칭(σ)·유연성(τ)의 의존도 그림. **정답 섞은 모델과 상위 15 겹침 수**로 어디까지 해석할지 결정(참고 팀 10쪽 방식).
- F5(LLM 규칙)의 대조 실험: 같은 열 수(101)의 **LLM과 무관한 특징**(예: 무작위 SMARTS 개수, Mordred 부분집합 무작위 101열)을 F0에 붙였을 때의 ΔMAE와 비교 → F5 효과가 "LLM 지식"인지 "열 추가"인지 판정.

### X5. GIN 하이브리드 설명
- 가지 기여도: 그래프 벡터(64)와 기술자(217) 중 어느 쪽에 의존하나 — 각 가지를 validation에서 순열(permutation)했을 때 MAE 증가.
- 원자 기여: Integrated Gradients(2주차 `xai.py`) → Joback 원자 기여와 순위 상관(2주차 그래프만 GIN은 ρ 0.61), 학습 안 한 모델·무작위·seed 일치도 포함. 기술자를 붙인 뒤 원자 지도가 어떻게 달라졌는지.
- **LGB와 GIN이 크게 엇갈리는 분자**(|예측 차| 상위 50): 어떤 계열인지, 누가 맞았는지 → "GIN이 트리와 다르게 틀리는 이유"(오차 상관 0.88)의 구조적 설명.

### X 산출물
`phase4_xai\XAI_REPORT.md`(한국어, 결론 3줄 → 오차 예산표 → X2–X5), 그림(오차 예산 막대, 오차 SHAP, 고융점 분류 AUC, 엇갈림 분자), 표·스크립트. 예산 제안: CPU 10 core-h 이내.

## 트랙 G — GIN 하이브리드 튜닝

### G1. 방법
- **Optuna TPE + 중간 중단(ASHA 또는 Hyperband pruner)**, SQLite 저장. 시도마다 epoch별 내부 검증 MAE를 report해서 가망 없는 시도를 초반에 끊기.
- 채점: train 안 고정 내부 분할(1차 T2와 같은 90:10, 모든 시도 공통), 탐색 중 seed 1개. validation은 탐색에 쓰지 않음.
- 탐색 전에 **1차 설정을 같은 틀에서 1회 재현**해 기준 내부 MAE 확보.

### G2. 탐색 공간 (제안 — Plan에서 조정 가능)
| 변수 | 범위 |
|---|---|
| conv 종류 | GIN / GINE(결합 특징 사용) |
| 층 수 | 3–6 |
| hidden | 64 / 128 / 256 |
| readout | mean / mean‖max / attention (sum은 제외: 녹는점은 세기 성질, 1·2주차 결과) |
| 그래프 벡터 차원 | 32 / 64 / 128 |
| **붙이는 기술자** | F0 / F0+F5 / F0+F3+F5 (1차에서 안 해 본 것 — 우선 확인) |
| 기술자 가지 | 그대로 붙임 / 작은 MLP(64–256)를 거쳐 붙임 |
| 결합 MLP | 폭 128–512, 1–3층 |
| dropout | 0–0.5 |
| 학습률 / weight decay | 3e-4–3e-3 (로그) / 1e-6–1e-2 (로그) |
| batch | 64 / 128 / 256 |
| 손실 | MSE / Huber(δ 60 K) |

### G3. 순서와 예산
1. **파일럿(약 3 core-h)**: 기술자 세 가지(F0 / F0+F5 / F0+F3+F5)만 1차 설정으로 비교. 차이가 크면 이후 탐색에서 고정.
2. **본 탐색(random, 약 12 core-h)**: 25–30 시도, pruner로 절반 이상을 30 epoch 안에 중단. 15 시도 뒤 최선 이득이 1차 설정 대비 0.5 K 미만(seed SD 약 0.3 K 수준)이면 중단하고 보고.
3. **scaffold(약 4 core-h)**: 내부 분할을 Murcko 그룹 단위로 한 별도 소규모 탐색(8–10 시도) 또는 random 상위 3개 설정 재평가.
4. **확정(약 6 core-h)**: 상위 2개 설정 × seed 3으로 재학습 → **validation**에서 1차 GIN 하이브리드(seed 3 평균)와 짝지은 CI. **이번에는 가중치(.pt)를 저장.**
5. **앙상블 다시 보기**: 튜닝된 GIN으로 B(LGB F0+F3+F5 + GIN 50:50)와 A 방식 가중치를 validation에서 다시 계산. GIN이 좋아지면 LGB와의 오차 상관이 올라가 앙상블 이득이 줄 수 있으니 상관도 같이 보고.
- 총 약 25 core-h, 동시 실행 2개까지(실행당 RAM 1.2 GB 이상). GPU가 연결돼 있으면 비용 추정을 먼저 보여 주고 승인받기.
- 1차에서 커널·프로세스 시작이 수십 분 멈춘 적이 있음 → 긴 학습은 처음부터 백그라운드 스크립트로, 검증된 `mlstudy` 실행 래퍼 사용.

### G4. test 사용 규칙 (중요)
test는 1차에서 이미 한 번 열었습니다. 두 번째로 열면 선택 편향이 생기므로:
- 열기 전에 **후보 1개**(예: "LGB F0+F3+F5 + 튜닝 GIN 50:50")와 판정 기준을 `phase4_gin_tune\PREREG.md`에 고정하고 **승인을 받은 뒤** test 1회.
- 보고서에는 "test 2회째 개봉"이라고 명시하고 1차 결과(B 24.76 / 33.99)와 나란히, 중복 제거 test(n 1,896)도 함께.
- validation에서 1차 GIN 대비 개선 CI가 0을 포함하면 test는 열지 않음.
