# T8 자연어·LLM 트랙 결과 (2단계, validation 전용)

> **2차(재승인 후) 결과는 12절**: zero-shot 회상 신호 있음(유명 분자), N3는 N2보다 나쁨(잠정, 토큰 한도로 18 %만 생성), M4 few-shot은 XGBoost와 차이 없음이나 기억 누설 위험으로 후보 제외. '자연어로 바꾸면 무엇을 얻고 잃는가'는 12.6절.

작성: 2026-11-21. 모든 수치는 저장한 CSV를 코드로 다시 읽어 옮겼다. 단위는 K, test 행은 학습·예측 어디에도 쓰지 않았다.
판정은 짝지은 부트스트랩 2,000회 95 % CI(`mc.paired_bootstrap`), ΔMAE = 후보 − 비교 기준(음수 = 개선).

## 0. 요약

1. **M2(LLM 규칙 → RDKit 특징 F5)는 두 분할 모두에서 같은 head의 RDKit 217보다 유의하게 좋다.** XGBoost head, seed 3개 평균 예측끼리 비교: random val −0.70 K [−1.06, −0.37] (26.499 대 27.204 K, n 1,995), scaffold val −0.85 K [−1.25, −0.41] (35.477 대 36.322 K, n 1,994). 중복 제거 기준에서도 같다(−0.75 / −0.84 K). 1단계 오차 분해가 지목한 2D 고대칭 계열과 > 550 K 구간에서 이득이 더 크다(train OOF + validation 합침: 고대칭 −0.88 / −1.55 K, > 550 K −1.97 / −2.70 K, random / scaffold). 가설 H21의 예상 범위(−0.5 ~ −0.1 K)보다 크다.
2. **N2(구조 템플릿 서술 → 범용 문장 임베딩)는 '텍스트로 바꾸면 잃는 양'의 대조군이다.** XGBoost head에서 RDKit 217보다 bge-small +8.04 / +7.65 K, MiniLM +9.43 / +8.36 K 나쁘다(random / scaffold). H20의 예상 범위(+2 ~ +8 K)의 상단이며, 사전 기준("16k에서 기술자보다 5 K 이상 나쁘면 M3로 진행하지 않음")에 걸린다.
3. **N1(PubChem IUPAC 이름 → MiniLM)이 가장 나쁘다.** XGBoost head +11.43 / +13.41 K. PubChem 미등재(이름 없음) 층에서 특히 나쁘다(+19 K).
4. **N3 500분자 파일럿**: 실패 0, 출력 잘림 1, 금지어 필터 탈락 1(0.2 %, 'pi-electron density' 오탐), 수동 점검 20개 중 15개 정확·5개 사소한 오류·골격 오류 0. 비용 0.108 USD. 실측 출력 토큰(호출당 269.5)이 사전 가정(120–200)보다 길다. **N3 전체(19,945건) Haiku 5.5 재추정: 플랫폼 경유 4.15 USD(재생성 10 % 가산 4.57), 직접 Batch API 1.59 USD.** 재승인 요청은 6절.
5. 비용: CPU 7.80 core-h(ledger 실측 합, 예산 16), API 0.451 USD(한도 2 USD; M2 규칙 제안 0.343 + N3 파일럿 0.108).

## 1. 실행 조건

- 분할: `splits/random.csv`, `splits/scaffold.csv`(고정). 중복 제거 validation: random n 1,922, scaffold n 1,986.
- head (a) Ridge: train 안 5-fold CV(목표 MAE)로 alpha 선택, train으로만 적합한 전처리(inf→NaN, 중앙값 대치, 0.5/99.5 백분위 자르기, 표준화). 결정적이라 seed 1회.
- head (b) XGBoost: `mc.BASE_XGB`, n_jobs=8, seed 42 / 0 / 1(42는 1단계 기준선과 같은 seed; seed 42 재적합은 1단계 기준선 예측과 최대 3e-5 K 차이로 일치). 후보 예측은 seed 3개 평균.
- 비교 기준 표현 = RDKit 217(캐시 `X_desc217.npy`)을 같은 head·같은 seed로 다시 적합한 것. seed 3개 평균은 그 자체로 배깅 이득이 있으므로(1단계 단일 seed 기준선 대비 random −0.40 K [−0.62, −0.18], scaffold −0.03 K [−0.31, +0.26]) **주 비교는 같은 head 대 같은 head**이고, 1단계 기준선 대비 값은 표 1b에 따로 둔다.
- 표본 수 곡선: train에서 무작위 1,000 / 4,000개(부분표본 seed 0, 1, 2; 각각 XGBoost seed 42, 0, 1) + 전체. 곡선 값은 **시드(부분표본)별 MAE의 평균 ± SD**이다(seed 평균 예측의 MAE는 서로 다른 부분표본의 배깅이라 곡선에는 쓰지 않았다).

## 3. M2 상세 — LLM 규칙 제안과 구현

- 호출: `host.llm`, 모델 claude-opus-5-5 2회 — (i) 문헌 지식 규칙 39개, (ii) train 200분자(SMILES + MP)만 보여 주고 데이터 규칙 25개. 보여 준 200분자는 **random·scaffold 두 분할 모두의 train**에 있고 InChIKey 첫 블록이 어느 분할의 validation·test와도 겹치지 않는 12,581개 중에서 seed 0으로 뽑았다({{artifact:1c8c593d-99a7-4231-8375-c9828ea16525}}). 프롬프트·응답 원문: {{artifact:6955d8bb-d05c-4b3d-b1f4-c5d1bedbe736}}, {{artifact:0302e330-cc64-4de6-a09c-514ceef60899}}, {{artifact:91b4d1f8-95c1-4422-800f-f3eec103f125}}, {{artifact:dc365c88-3ee0-4162-984b-123b34d9f747}}.
- 구현: 64개 규칙 → F5 101열(6개 묶음). 완전 구현 52개, 부분 구현 12개, 미구현 0개. 부분 구현 사유(예: 3D 회전 대칭수 대신 2D 그래프 자기동형 수, 메소 판정 미구현, 할로젠 결합의 전자 부족 조건 생략)는 규칙 대응표 {{artifact:3f34d87d-bbfd-4114-9aa5-11d34ef7a322}}에 있다. `ionic_multi` 열은 데이터에 해당 분자가 없어 모두 0이다. 코드: {{artifact:87cdbc20-3a97-4b06-a1a2-250cb17441b8}}, 특징 행렬: {{artifact:4531935f-b7e9-4baa-95d7-6d717e6b526f}} (19,945 × 101 float32, mp.csv 행 순서), CSV판 {{artifact:a261d705-3d21-428e-8280-7656a3363d62}}. 계산 96 s(단일 스레드, 1,000분자당 4.8 s).

## 7. 다음 단계 계획 (기억 누설 점검 설계 포함)

1. M2 F5를 트리 부스팅 트랙(튜닝 XGBoost/LightGBM)과 앙상블 트랙에 넘긴다. 튜닝된 모델에서 F5 이득이 유지되는지(참고 팀 결정 특징 13개는 튜닝 모델에서 −0.25 K로 줄었음)를 같은 짝지은 CI로 확인해야 한다.
2. 기억 누설 점검 설계(재승인 후):
   - (a) zero-shot 회상: 위 1번. 회상 신호가 있으면(분자-무관 일치율 대비 유의하게 높음) 그 분자 집합을 '기억 의심'으로 표시한다.
   - (b) N3 이득의 층화: N3 − N2 ΔMAE를 동의어 3분위·'기억 의심' 여부로 나눈다. 이득이 유명/기억 의심 층에만 있으면 기억 효과로 판정하고 결과로 쓰지 않는다(H23 실패 기준).
   - (c) 서술 내용 감사: 숫자+단위·물성 단어 필터(파일럿 탈락 0.2 %) + 서술에 화합물 이름이 나오는지 PubChem 동의어 목록과 대조(파일럿에서는 이름 금지 지시만 했고 대조는 하지 않았다).
   - (d) M4: 이웃 평균 대조 + 이웃에서 정답 분자의 첫 블록 일치 제거(중복 제거 기준을 주 기준).
3. M3(소형 LM 미세조정)는 N2 결과(XGBoost head에서 +7.6 K 이상)가 사전 중단 기준에 걸려 진행하지 않을 것을 권한다.

## 10. 편차·주의

1. 시작 시 PowerShell 도구가 샌드박스 초기화 오류로 실패해 폴더 생성·복사를 python으로 했다. mp-push 환경에 `requests`가 없어 PubChem 조회는 표준 라이브러리 `urllib`로 했다.
2. bge-small 임베딩은 XGBoost와 경합해 느려서 첫 2,000개 조각 뒤 중단했다가 재개했다(조각 저장으로 결과 영향 없음). 중단 전 조각의 CPU는 추정 가산(0.34 core-h)이다.
3. 약 20분 동안 무거운 작업 3개(XGBoost 2개 + 임베딩)가 동시에 돌았다(PREREG 8절 '동시에 2개까지' 초과). 결과에는 영향이 없고 벽시계·문장당 시간이 늘었다.
4. N2 템플릿 생성의 CostMeter는 동시 실행 중이던 자식 프로세스 CPU를 함께 세어 벽시계 × 1코어(0.045 core-h)로 대체했다. ledger의 CPU는 CostMeter 실측이며 커널 쪽 분석 작업 일부는 빠져 있다.
5. 표 3의 'OOF+val 합침'은 seed 42 단일 OOF와 seed 3 평균 validation을 합친 진단값이다.
6. N3 비용 재추정의 zero-shot·M4 출력 토큰(8)은 가정이고, Sonnet·Opus 행은 Haiku와 같은 토큰 수를 가정했다. 단가는 2차 출처라 결제 전 공식 확인이 필요하다. 처음 만든 비용표는 Sonnet 캐시 읽기를 0.20으로 잘못 넣었고(파일 값 0.10), 검토 지적 후 고쳤다(Sonnet N3 전체 플랫폼 83.09 → 73.34 USD; Haiku 행은 변화 없음).

## 11. 기억 누설 점검(H26) 판정 기준 — 2차 실행 전 고정 (2026-11-21, zero-shot·N3 전체·M4 실행 전에 작성)

이 절은 zero-shot 회상률 점검, N3 전체 서술, M4 few-shot을 실행하기 전에 적었다. 실행 뒤 바꾸면 이 절 끝에 날짜·이유를 남긴다.

**층화 변수**
- S1 PubChem 등재/미등재(`n1_pubchem_names.csv`의 in_pubchem). 등재율이 97.7 %라 보조 변수로만 쓴다.
- S2 유명도: PubChem 동의어 수(n_synonyms) — 분할별 validation 안 3분위의 상위 1/3(유명) 대 하위 1/3(희귀). 미등재는 희귀 쪽에 넣지 않고 따로 보고.
- S3 zero-shot 회상: 1단계의 200분자에서 SMILES 또는 이름 변형 중 하나라도 |LLM 답 − 라벨| ≤ 5 K이면 '회상 성공', 아니면 '실패'. 이 층화는 200분자 안에서만 쓴다.

**통계량**
- 같은 분자에서 Δ = |오차|(텍스트·LLM 모델) − |오차|(대조 모델). 상호작용 I = mean Δ(유명 또는 회상 성공) − mean Δ(희귀 또는 회상 실패). 층 안에서 따로 복원 추출하는 부트스트랩 2,000회 95 % CI.
- 주 대조(사전 지정): ① N3 − N2(같은 임베딩 모델·같은 head; 'LLM이 쓴 문장'이 템플릿보다 더 주는 것), ② M4 − kNN 기준선(같은 20개 이웃의 Tanimoto 가중 평균; 'LLM이 이웃 평균 이상으로 주는 것'). 보조 대조: N1·N2·N3·M4 각각 − RDKit217(XGBoost), 그리고 기술자 계열 M2 − RDKit217을 같은 층으로 계산해 '기술자 계열에도 같은 층 패턴이 있는가'를 함께 본다.
- 분할 격차: 텍스트 계열과 기술자 계열의 (scaffold MAE − random MAE)/random MAE 를 비교. 기억에 기대는 모델은 분할에 덜 민감하므로 격차가 작아진다.

**판정 규칙**
1. zero-shot 회상 신호 = 200분자에서 |오차| ≤ 1 K 비율 또는 ≤ 5 K 비율 또는 정수 일치율(|오차| ≤ 0.5 K; 라벨이 °C + 273.15라서 °C 정수 일치와 같음)이 분자-무관 기준(LLM 답을 분자 사이에서 섞은 순열 2,000회, 그리고 train 라벨 분포에서 무작위로 뽑은 값)보다 높고 순열 p < 0.05. 변형(SMILES, 이름)별로 판정.
2. **기억 효과 있음**으로 판정하는 조건: 주 대조 ①이나 ②에서 I의 95 % CI 상한 < 0(유명/회상 성공 분자에서만 텍스트·LLM 쪽이 유독 좋음) **이고** 같은 층에서 기술자 계열(M2 − RDKit217)의 I는 CI가 0을 포함하거나 반대 부호. 또는 1번의 회상 신호가 있고, 회상 성공 분자에서 N3·M4의 이득이 집중(I CI 상한 < 0).
3. 위 조건이 없으면 '기억 효과 증거 없음'으로 적되, 표본 크기(층별 n)와 CI 폭을 함께 적는다. 1번 회상 신호만 있고 2번이 없으면 'LLM은 일부 녹는점을 기억하지만 이 파이프라인의 이득으로 이어지지 않음'으로 적는다.
4. 기억 효과가 있다고 판정되면 해당 후보(N3 또는 M4)는 앙상블 후보에서 빼거나, 회상 성공·유명 층을 제외한 성능만 보고한다.


**11절 변경 기록 (2026-11-21, 실행 후)**: 판정 규칙 2의 '회상 성공 분자에서 N3·M4의 이득 집중' 중 M4 부분은 적용할 수 없었다. M4 300분자를 지시대로 zero-shot 200분자와 겹치지 않게 뽑아, M4 표본에는 회상 성공/실패 표지가 없기 때문이다. 이 문제는 결과를 보기 전에 표본 설계 단계에서 생겼다. M4는 S2(유명도) 층화로만 판정했고, S3는 N3(확보분 중 zero-shot 표본 49분자)에만 적용했다.

**판정**
1. 규칙 1(zero-shot 회상 신호): **있음.** 유명 분자에서 LLM이 녹는점을 RDKit217보다 자주 ±5 K, ±1 K 안으로 맞힌다.
2. 규칙 2(주 대조의 유명/회상 층 상호작용 CI 상한 < 0): **해당 없음.**
   - N3 − N2(4개 조합)의 I는 모두 CI가 0을 포함한다. random 분할에서는 점추정이 오히려 양수(유명 층에서 N3가 더 나쁨)다.
   - M4 − kNN은 k=20에서 I = +4.63 [-6.05, +17.24], k=5에서 -1.48 [-12.04, +9.41]다.
   - 다만 M4의 층별 n이 99 / 92라 CI 폭이 20 K를 넘어, 검정력이 낮다.
3. 결론(규칙 3): **"LLM은 유명 분자의 녹는점 일부를 기억하지만, N3 서술 경로의 성능 이득으로는 이어지지 않는다(N3는 N2보다 나쁨)."**
   - M4는 '기억 효과 증거 없음'이지만 판정력이 약하다.
   - M4와 zero-shot이 학습 없이 XGBoost 수준인 이유가 일반 화학 지식인지, 공개 데이터(Bradley, CC0)를 사전학습에서 본 것인지는 희귀 분자에서 구분할 수 없다. 그래서 **M4는 test 최종 후보로 쓰지 않을 것을 권한다.** test 분자도 같은 공개 데이터에 있으므로 분할 설계로는 이 누설을 막을 수 없다.
4. 대조 관찰:
   - LLM이 개입하지 않는 N1·N2(로컬 임베딩)도 유명 층에서 더 나쁘다(validation 전체 random I +4.8 ~ +5.9 K). 유명 분자, 곧 복잡한 의약·천연물 계열이 텍스트 표현에 본래 어렵다는 뜻이다.
   - 기술자 계열 M2는 random 유명 층에서 조금 더 좋다(I −0.86 [−1.72, −0.02]).
   - 분할 격차 기준은 약한 모델일수록 상대 격차가 작아지는 효과(N2: −0.09 ~ −0.12)와 섞여 있어, 기억 판정에는 쓰지 않았다.

### 12.6 "분자를 자연어로 바꾸면 무엇을 얻고 잃는가"

1. **잃는 것: 정량 구조 정보.** 기술자와 같은 정보를 담은 템플릿 문장(N2)도 범용 문장 임베딩을 거치면 같은 XGBoost에서 7.6–9.4 K를 잃는다. 데이터를 1k에서 16k로 늘려도 이 간격은 random에서 1–2 K 줄 뿐이고, scaffold에서는 오히려 늘어난다.
2. **LLM이 쓴 산문(N3)은 템플릿보다 더 잃는다**(잠정: N2 대비 +2.6 ~ +4.7 K; random XGBoost 두 임베딩은 CI가 0을 제외하고, scaffold는 n 216이라 CI가 0을 포함). 개수·위치가 산문으로 흐려지고, 20개 중 5개에 사소한 구조 오류가 있었다. IUPAC 이름(N1)이 가장 나쁘다(+11 ~ +13 K).
3. **얻는 것은 '텍스트'가 아니라 'LLM의 화학 지식'이다.** 그 지식을 규칙으로 받아 RDKit 코드로 옮긴 M2만 두 분할 모두에서 이겼다(−0.70 / −0.85 K). 이득은 대칭·유연성 규칙에서 나왔고, 비용은 LLM 호출 2회(0.34 USD)였다.
4. **LLM을 직접 예측기로 쓰면 학습 없이 XGBoost와 통계적으로 구분되지 않는 수준**(few-shot 29.4 K 대 27.3 K)까지 간다. 그러나 유명 분자에서 회상 신호가 있고, 공개 데이터를 기억했을 가능성을 배제할 수 없어 일반화 성능으로 해석할 수 없다.
5. **텍스트 임베딩을 기술자에 붙여도 얻는 것이 없다**(N3: random +2.3 K, scaffold −0.3 K, CI 0 포함). 추론 비용은 임베딩 경로가 F5 경로의 20–40배이고, LLM 경로는 분자마다 API 호출이 든다.
6. 실무 결론: 이 데이터 규모(1.6만)에서 자연어는 **예측 입력이 아니라 특징 설계의 도구**로 쓸 때만 이득이 있었다.

### 12.9 2차 편차

1. 2차 단계 제목 5개('zero-shot 회상률 점검 (재승인 후)' 등)는 `update_step_status`에 등록되어 있지 않아 상태를 기록하지 못했다.
2. zero-shot 문구를 두 번 바꿨다(v1 거부 → v2 → v3 도구 강제). 추가 호출 792건, 0.060 USD.
3. N3: 토큰 한도로 3,560 / 19,445건만 생성했다(18 %). 재시도는 불가능했다. N3 비교는 대표성이 없는 4,044분자 부분집합의 잠정 결과이고, 곡선은 1k와 3.3k / 3.7k 두 점뿐이다. MiniLM은 N3 서술 0.02 %(1건)를 256토큰에서 잘랐다.
4. M4는 N3 생성과 시간상 겹쳐 실행했다(단계 순서 편차). 동시성은 2로 낮췄다. 도구 정의 때문에 입력 토큰이 호출당 929개(k=20)로 비용표 추정(641)보다 컸다.
5. M4 300분자는 zero-shot 200분자와 겹치지 않게 뽑아서(지시대로) S3(회상 성공) 층화는 M4에 적용할 수 없다.
6. N3 확보분 scaffold validation의 유명도 층은 104 / 19분자로 치우쳐 있다(경계는 scaffold validation 전체에서 계산).
