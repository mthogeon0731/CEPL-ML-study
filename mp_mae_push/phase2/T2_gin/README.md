# T2 GIN 슬롯 — 수업 GIN(mean) + RDKit 기술자 217 하이브리드 readout (2026-11-21)

## 편차
- 범위 축소 없음. 계획한 6회(3 seed × 2 분할)와 그래프 전용 대조 2회(seed 1, 두 분할)를 모두 돌렸다. 총 6.46 core-h로 예산 8 core-h 안이다.
- torch 스레드는 지시서 환경 메모의 4가 아니라 **1**로 고정했다. 3 epoch 측정에서 epoch당 core-h가 4스레드 0.0134, 2스레드 0.0087, 1스레드 0.0077이었기 때문이다. 대신 1스레드 대기열 2개를 동시에 돌렸다. 모든 본 실행이 같은 스레드 수이고, ledger `params`에 적었다.
- 기준선과의 짝지은 CI는 **단일 seed XGB validation 예측**(27.607 / 36.348 K)으로만 냈다. XGB seed 3 평균(27.20 / 36.32 K)은 예측 파일이 없어 MAE 차이만 적었다.
- ledger에 없는 비용이 있다. 첫 파일럿 시도는 ledger 열 충돌로 그래프 생성 직후 멈췄다(약 0.03 core-h 추정). 대기열 첫 실행 2회는 함수 정의 순서 오류로 데이터 읽기 직후 멈췄다(각 < 0.01 core-h). 이를 더하면 총 약 6.5 core-h다.
- 분석 커널(`python` 환경)에 psutil이 없어서 `mpcommon`을 import할 때만 psutil 대용 모듈을 넣었다. 분석에 쓴 `paired_bootstrap`과 `metrics`는 psutil을 쓰지 않으므로 수치 영향은 없다. 학습 자체는 래퍼로 mlstudy 환경에서 돌았다.

## 설정 (실행 전 고정, validation으로 고르지 않음)
| 항목 | 값 |
|---|---|
| 그래프 | 수업 `feature.py` 그대로: 원자 147, 결합 16. PyG GIN은 edge_attr를 쓰지 않음(수업과 같음) |
| GNN | PyG `GIN` 5층, hidden 128, 출력 64, dropout 0.3 → `global_mean_pool` |
| 하이브리드 readout | [z(64) ‖ 기술자 217] → MLP 281→256→128→1 (ReLU, dropout 0.3) |
| 기술자 | `cache/X_desc217.npy`. 표준화는 train 전체(15,955 / 15,956행)로 fit, ±10 클리핑, NaN→0(실제 NaN 0개) |
| 손실 | **SmoothL1(β = 0.25 σ_y, 표준화 y 단위)**. 지표가 MAE라서 큰 잔차에 L1처럼 작동하는 손실을 골랐다. 라벨에는 반복측정 범위 ≥ 50 K 같은 꼬리가 긴 잡음이 있다(1단계). 0 근처는 매끄러워 AdamW가 안정적이다. 수업 기본 MSE는 큰 잔차에 끌려간다 |
| 최적화 | 수업 그대로: AdamW 1e-3, ReduceLROnPlateau(patience 10, factor 0.8, min 1e-6), 기울기 ±10 자르기, batch 256(N = 19,945 → 연구실 규칙), 최대 300 epoch |
| 조기 종료 | train 안 10 % 내부 분할(random: 무작위, scaffold: Murcko 뼈대 묶음을 seed별로 섞어 배정), 내부 MAE patience 30, 최적 가중치 복원. validation은 학습에 쓰지 않음 |
| y 스케일러 | 학습에 쓴 90 %(fit 14,359 / 14,361행)로 fit |
| 스레드 | torch 1 (interop 1), DataLoader num_workers 0 |

- 최종 모델은 train의 90 %로 학습했다(나머지 10 %는 조기 종료용). 100 %로 다시 학습하지는 않았다. 1단계 학습 곡선(2배당 −1.73 K)으로 보면 이 때문에 약 +0.26 K 손해로 추정한다(추정치).
- 소스는 수업 코드 4개(feature, models, datamanager, train)를 `src/`로 복사했다. `models.py`에는 `HybridGraphRegressor`를 추가했고, `train_hybrid.py`는 `train.py`에서 파생한 새 파일이다. 원본은 수정하지 않았다.
  [models.py]({{artifact:72252e42-de82-4806-b9e9-5da07219e347}}), [train_hybrid.py]({{artifact:d6cd8855-090c-4c0a-ab64-7df393a706ae}}), [analyze_t2.py]({{artifact:df5601f9-dc26-4018-8552-5bcbb27815e8}}), [q_random.py]({{artifact:7e0eee6c-fa87-4b26-84aa-c143c1f519cd}}), [q_scaffold.py]({{artifact:6a6849ed-46c5-43e0-ac89-5c0a4d2d14bf}})

## GBDT 대비 해석
1. **단일 모델끼리 비교하면 XGB와 같은 수준이다.** random은 seed 평균 27.43 K로, XGB 단일 27.607보다 0.17 K 낫고 XGB seed 3 평균 27.20보다 0.23 K 나쁘다. scaffold는 36.80 K로 XGB보다 0.45–0.48 K 나쁘다. 개별 seed의 짝지은 CI는 모두 0을 포함한다.
2. **seed 3개 예측 평균은 XGB 단일보다 유의하게 낫다**(random −1.35 [−2.07, −0.65], scaffold −0.97 [−1.83, −0.14] K). 다만 3개 모델 앙상블과 1개 모델의 비교다. 신경망은 seed 분산이 커서 평균의 이득이 크다(개별 대비 −1.2 / −1.4 K). XGB seed 평균 예측과의 공정한 비교는 앙상블 트랙에서 해야 한다.
3. **기술자를 붙이는 효과가 크다.** 그래프 전용 GIN(같은 head, seed 1)은 random 30.46 K, scaffold 44.95 K였다. 하이브리드 seed 1 대비 −2.82 / −8.52 K이고, scaffold에서 특히 크다. 그래프 전용 수치는 seed 1개라 잠정치다. 다른 팀의 전체 데이터 GIN mean(30.2 / 43.3 K)과는 비슷하다.
4. **앙상블 후보로 넘길 만하다.** XGB 단일과의 오차 상관이 random 0.874, scaffold 0.897로 1보다 충분히 낮다. 진단용으로 가중치를 튜닝하지 않은 50:50 혼합(GIN seed 평균 + XGB 단일)은 random 25.98 K(−1.62 [−2.02, −1.23]), scaffold 34.79 K(−1.56 [−2.00, −1.11])였다. 이 혼합도 같은 validation에서 잰 것이라 최종 가중치는 앙상블 트랙이 정한다([diag_blend50_vs_xgb.csv]({{artifact:0cec6623-295d-406e-b3ec-e08966532e91}})).
5. **비용.** 학습은 XGB 한 번보다 훨씬 비싸다(하이브리드 6회 4.1 core-h). 추론은 기술자 계산이 지배하므로 XGB + 기술자와 비슷하다. 그래프 생성 4.8 s/1k를 더해도 기술자 21.8 s/1k보다 작다.

## 실패한 시도
1. 첫 파일럿: ledger 행에 `stage`를 두 번 넘겨 TypeError가 났다. 그래프 캐시를 지우고 다시 돌려 생성 비용을 ledger에 남겼다.
2. 첫 대기열 실행: `run_queue`가 `__main__` 블록 뒤에 정의돼 NameError가 났다(두 프로세스 모두 데이터 읽기 직후 종료). 블록 순서를 고쳐 다시 실행했다.
3. 예산 가드의 '실행당 추정'은 끝난 실행의 최댓값을 쓴다. scaffold가 먼저 끝나 random 실행을 0.34 core-h로 과소추정했지만, 실제 총합이 예산 안이라 영향은 없었다.
