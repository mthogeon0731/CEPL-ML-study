# T1 트리 부스팅 트랙 보고 (2026-11-21)

모든 수치의 단위는 K이다. validation만 썼고 test 행은 예측하지 않았다. 기준선은 XGBoost(600그루, lr 0.05, depth 6, subsample 0.8, colsample 0.5, n_jobs 8, random_state 42) + RDKit 기술자 217개(F0)이며, validation MAE는 random 27.607 (n 1,995) / scaffold 36.348 (n 1,994)이다. 기준선 예측 파일을 그대로 재현했다(최대 차이 3e-5 K). ΔMAE는 이 기준선 예측에 대한 짝지은 부트스트랩(2,000회) 결과이며, 음수가 개선이다. 중복 제거 validation은 random n 1,922, scaffold n 1,986이다. 트랙 총비용은 **21.376 core-h**(상한 22)이고, XGBoost는 항상 n_jobs=8, LightGBM은 num_threads=8로 돌렸다.

## 편차 (계획과 다르게 한 것)

1. **trial 수 축소**: XGBoost study는 42/50, LightGBM study는 35/50 trial에서 각자 CPU 상한(6.0 / 2.5 core-h)에 걸려 멈췄다. 두 study 모두 0.4 K 중단 규칙은 통과했다(내부 이득 1.22 / 1.01 K). LightGBM의 최선값은 10 trial에 26.817, 35 trial에 26.813이어서 사실상 수렴한 상태였다. XGBoost는 40 trial 26.670에서 41 trial 26.605로 아직 조금씩 내려가고 있었다.
2. **scaffold 전용 탐색 생략**: 예산이 남지 않아 지시대로 random 최선 설정을 scaffold에 그대로 적용했다. 다만 나무 수는 scaffold 내부 분할(Murcko 그룹)에서 같은 설정으로 조기 종료를 한 번 돌려 정했다.
3. **버그가 있던 첫 XGBoost study를 폐기**(`xgb_random_F0`, 완료 13 + 실패 1 trial, 1.191 core-h). pseudo-Huber에 base_score(학습 중앙값)를 주지 않아 trial 2개가 발산했다(내부 MAE 72,568 / 1,461,420 K). 1단계와 같게 고쳐 `xgb_random_F0_v2`로 처음부터 다시 돌렸다. 버그 study는 프로세스를 멈추려고 ledger를 잠시 읽기 전용으로 바꾸는 방식으로 끝냈다. 그 결과 trial 13의 ledger 기록이 실패해, 그 행은 Optuna 기록값(비용 0.155 core-h)으로 손으로 넣었다(notes에 표시). 비용은 합계에 들어 있다.
4. **scaffold 내부 분할 크기**: 큰 Murcko 그룹 때문에 GroupShuffleSplit(test_size 0.15, seed 42)이 14,573 / 1,383행(8.7 %)으로 나뉘어 85/15가 아니다. random은 13,561 / 2,394. 재적합 나무 수는 1/0.85 대신 best_iter × n_train / n_inner_train(random 1.177, scaffold 1.095)으로 늘렸다.
5. **OOF는 seed 1개(seed 0)**: 예산 때문에 seed 3개 평균이 아니다. 최종 후보 2개(xgb_r1, lgb_r1) × 두 분할.
6. **2단계 손실은 MSE로 진행**: validation 점추정 최선은 pseudo-Huber 60 K였다. 그러나 train 안 5-fold CV(seed 0, n 15,955)에서는 MSE가 유의하게 나았다(random +0.19 [+0.04, +0.35], scaffold +0.44 [+0.26, +0.62]). 같은 seed끼리 비교한 validation 차이도 유의하지 않아 MSE로 갔다. 대신 3단계 Optuna 공간에 손실을 범주형으로 넣었다(XGB: MSE / pseudo-Huber 60, LGB: MSE / Huber 60). 계획에 없던 범위 추가다.
7. pseudo-Huber slope CV는 사전 격자 10/30/60에서 두 분할 모두 끝값 60을 골랐다. 격자는 넓히지 않았다.
8. CatBoost는 쓰지 않았다(환경에서 import 실패, 예산 없음).
9. LightGBM 공간: max_depth는 범주형 {-1, 6, 8, 10, 12}이고 num_leaves는 로그 균등이다. min_sum_hessian은 탐색하지 않았다.
10. 상위 3개 설정: 내부 MAE 기준 상위 3개가 모두 XGBoost(r1–r3, 서로 거의 같은 설정)라 셋 다 재적합했다. 여기에 다양성과 앙상블 재료를 위해 LightGBM 최선(lgb_r1)을 하나 더 재적합했다. 4단계(O10)도 lgb_r1까지 했다.
11. O1 seed는 0–9를 썼다(기준선은 random_state 42). 단일 seed의 seed 0–9 평균 MAE가 기준선 단일 적합보다 random 27.445 대 27.607, scaffold 36.534 대 36.348이다. 그래서 '기준선 대비' ΔMAE에는 기준선 seed의 운이 섞인다. 같은 seed끼리의 비교도 함께 적었다.
12. 다른 트랙과 CPU를 나눠 써서 wall 시간이 1단계보다 3–10배 늘었다. `infer_s_per_1k`(추론 시간)는 경합 상태에서 잰 값이라 절댓값으로 믿기 어렵다.
13. test는 쓰지 않았다(규약 준수).

## 4. 실패하거나 효과가 없던 시도 (한 줄씩)
- H02 L1(absoluteerror): random +0.40 [+0.03, +0.81]로 MSE보다 나쁨, scaffold는 차이 없음.
- H02 분위수 0.5: random +1.97, scaffold +0.78 K로 MSE보다 유의하게 나쁨.
- H02 pseudo-Huber 60: 같은 seed 비교로 n.s., train CV에서는 MSE보다 유의하게 나쁨.
- H02 pseudo-Huber slope 10/30: CV에서 60보다 나쁨(격자 끝에서 단조 감소).
- O3 입체 특징: random에서 유의하게 나쁨(+0.29), scaffold는 n.s.(−0.17), 입체 부분집합에서도 n.s.
- H03 Morgan count: 두 분할 모두 n.s.이고 적합 비용은 약 6배.
- 첫 XGBoost Optuna study: pseudo-Huber base_score 누락 버그로 발산, 폐기(1.191 core-h 손실).
- 튜닝 설정의 scaffold 전이: xgb_r1 −0.13, xgb_r3 −0.08 K로 거의 효과 없음.
- 튜닝 XGB 3설정 × seed 3 배깅(xgb_top3x3): r3 단독보다 나아지지 않음(설정이 서로 너무 비슷하고 seed 분산이 작음).
